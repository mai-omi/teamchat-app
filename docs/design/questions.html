Q-01 サイドバーとチャンネル一覧には、公開チャンネルすべてと、自分がメンバーのプライベートチャンネルだけを出す想定です。自分がメンバーでないプライベートチャンネルは名前も出さない、ということでよいですか。 channel-show.html 等でメンバーの佐藤にだけ「採用プロジェクト」が出ている ／ spec 3-2・3-3 未回答
Q-02 チャンネルの公開範囲（公開／プライベート）は、作成後は変更できない想定です。これでよいですか。 channel-edit.html の注記「公開範囲はあとから変更できません」 未回答
Q-03 プライベートチャンネルからメンバーを外しても、その人が過去に書いたメッセージは残す想定です。また、外された人はその後、そのチャンネルを一切見られなくなる（過去分も含む）想定です。これでよいですか。 spec 3-3（追加・削除）／ spec 3-4（削除は跡を残す方針） 未回答
Q-04 検索の対象はメッセージ本文のみで、チャンネル名・説明・投稿者名は対象にしない想定です。これでよいですか。 spec 3-6「メッセージを探せる」 ／ search.html 未回答
Q-05 「このメッセージは削除されました」になったメッセージは、検索結果には出さない想定です。これでよいですか。 spec 3-4・3-6 ／ design-guide §4 未回答
Q-06 返信（スレッド）はメッセージに対して1段だけで、返信にさらに返信（入れ子）は付けられない想定です。これでよいですか。 spec 3-5「元のメッセージにぶら下がる」 ／ thread.html（1段のみ） 未回答
Q-07 メッセージの編集・削除は本人だけで、チャンネルの作成者でも他人のメッセージは編集・削除できない想定です（モデレーション機能は持たせない）。これでよいですか。 spec 3-4「他の人が書いたメッセージは直せません」 ／ spec 4（全体管理はスコープ外） 未回答
Q-08 同じ「削除」でも、相手によって決まりが変わります。メッセージを1件消したときは、確認なしで即時に消え、その場所に「このメッセージは削除されました」が残ります（本文は消えますが、投稿者・日時・返信件数は残り、前後のやり取りを追えます）。いっぽうチャンネルごと消したときは、チャンネル名の入力で確認したうえで、中のメッセージ・返信も含めて跡形なく消え、元に戻せません。チャンネルごと消す場合は、文脈を残す相手（前後のメッセージ）自体が無くなるため跡を残さない、という想定です。この2つの違いでよいですか。 spec 3-4（1件削除は跡を残す／その理由）／ channel-edit.html（チャンネル削除は「メッセージと返信もすべて削除され、元に戻せません」＋名前入力の確認）／ 関連: Q-18 未回答
Q-09 新規登録では、入力ミス防止のため**「パスワード（確認用）」を設け、一致を検証する**想定です（spec 3-1 には記載がありませんが、モックにあります）。これでよいですか。 register.html ／ spec 3-1 未回答
Q-10 メールアドレスはログインに使うため一意（重複登録は不可）、表示名は重複を許す想定です。これでよいですか。 spec 3-1（メールでログイン）／ spec 5-4（同姓同名を想定しない内容） 未回答
Q-11 ログイン後に最初に表示する画面は**チャンネル一覧（channels）**にする想定です。これでよいですか（特定チャンネルを開くなど別の入口が良ければ教えてください）。 spec に記載なし ／ index.html はカタログのみ 未回答
Q-12 チャンネル内のメッセージは古い順に全件表示し、ページング（続きを読み込む等）は行わない想定です。これでよいですか。 spec 3-4 ／ spec 4（自動表示はスコープ外だがページングの指定はなし） 未回答
Q-13 メンバー追加は、メールアドレスまたは表示名の完全一致で、既に登録済みの社員の中から選ぶ想定です（未登録の人の招待は行わない）。これでよいですか。 members.html「表示名またはメールアドレスで探す」／ spec 3-3 未回答
Q-14 公開APIはJSONを返す読み取り専用とし、メールアドレスなど個人を特定しうる情報は含めず、投稿者は表示名のみ・日時付きで返す想定です。削除済みメッセージは本文を返さず「削除されました」相当の扱いにします。これでよいですか。 spec 3-7 ／ spec 3-4 未回答
Q-15 公開APIのメッセージ一覧はチャンネル直下のメッセージを返し、スレッドの返信は本文としては含めず、返信件数だけを付ける想定です。これでよいですか（返信本文まで必要なら教えてください）。 spec 3-7 ／ spec 3-5 未回答
Q-16 返信件数には、削除された返信も含めて数える想定です（削除は跡を残す方針に合わせるため）。これでよいですか。 spec 3-4・3-5 ／ design-guide §4「返信件数の表示も消さない」 未回答
Q-17 退会（アカウント削除）・プロフィール変更・パスワード再設定は今回作らない想定です（spec に記載がないため）。これでよいですか。 spec に記載なし ／ spec 4（最小構成の方針） 未回答
Q-18 消したメッセージの本文を、データとしては残さない想定です。削除時に本文は消し（または空にし）、行だけを「削除済み」の印とともに残して、投稿者・日時・返信・返信件数は保持します（＝削除後は本文を元に戻せない）。これでよいですか。それとも、あとで復元・監査できるよう本文も保持しておきたいですか。 spec 3-4 は画面に「このメッセージは削除されました」を残すとだけ指定。データとしてどう持つかは未指定 未回答
