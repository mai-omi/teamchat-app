# 確認事項リスト

仕様書に書かれておらず、モックアップだけでは決めきれないところを、**こちらの想定を添えて**挙げます。
「このまま進めてよいか」「違う場合はどうするか」を、まとめて教えてください（spec 6章「まとめて回答します」）。

- 回答は下の「回答・決定ログ」に、もらったまま載せています。
- 各Qの「状態」は **回答済み／一部回答／回答なし／自分で決めた／保留** で示します。クライアントの回答を待たず、こちらの責任で決めたものは「自分で決めた」とし、根拠・理由を各行に添えています。いまは決めず、別のところで決めるものは「保留」とし、どこで決めるかを添えています。
- 一部しか答えが返っていなかったものは、返ってきていない部分をこちらで決め、回答ログにその旨を書いています。
- design-guide で「実装の判断」と明記されている点など、もともと確認不要のものは末尾の「自分で決めたこと」に分けています。

## 回答・決定ログ

2026-11-09、クライアントから回答が返ってきました。全文を、もらったまま（表現を変えずに）下に載せ、1本ずつ対応する Q に対応づけています。

### 対応する Q があった回答

**Q-01 → 回答済み**
- （質問）入っていないプライベートチャンネルは、名前だけでも見えますか
- （回答）見えないようにしてください。チャンネルの一覧にも出さないでください。「そういう部屋がある」ということ自体が分からない状態にしたいです。

**Q-08 → 回答済み**
- （質問）チャンネルを消したら、中のメッセージはどうなりますか
- （回答）一緒に消えて構いません。ただ、うっかり消してしまうと戻せないので、消す前に確認を出してください。

**Q-04 → 回答済み**
- （質問）（検索は）何を対象に探しますか
- （回答）メッセージの本文だけで構いません。チャンネル名や人の名前で探す機能は、今回は要りません。

**Q-06 → 回答済み**
- （質問）返信に対して、さらに返信を重ねられますか
- （回答）今回は要りません。返信は1段までにしてください。何段も重なると、結局どこに何が書いてあるのか分からなくなります。

**Q-12 → もとは一部回答。残りは自分で決めた**
- （質問）メッセージはどの順番で並びますか
- （回答）古いものが上、新しいものが下でお願いします。モックアップの並びのとおりです。
- 残りの決定：並び順（古い順）は回答どおり。表示件数は、こちらで決めて **100件ごとのページング** とした（Q-12 本文参照）。

**Q-14 → もとは一部回答。残りは自分で決めた**
- （質問）削除されたメッセージは、APIの結果に含まれますか
- （回答）含めないでください。外から見えるところに「削除されました」が並ぶ必要はありません。
- 残りの決定：JSON・読み取り専用／メール等を含めない／投稿者は表示名のみ・日時付き、を自分で決めた（Q-14 本文参照）。
- 削除メッセージの扱い：クライアント回答に合わせ、**APIからは完全に除外**（「削除されました」も出さず、件数にも数えない）に決定（2026-11-09、当初の「『削除されました』相当で返す」案から変更）。

**Q-17 → もとは一部回答。残りは自分で決めた**
- （質問）登録したあとに、名前やパスワードを変える画面は要りますか
- （回答）今回は要りません。必要になったら、あらためてご相談します。
- 残りの決定：併せて **退会（アカウント削除）も今回は作らない** と自分で決めた（Q-17 本文参照）。

### どのQにも当たらなかった回答

既存の Q に対応しない、新しい論点です。残しておきます（Q として起こすか設計に反映するかは、次の指示を待ちます。ここではこちらで決めません）。

- （質問）同じ名前のチャンネルを作れてよいですか
  （回答）作れないようにしてください。同じ名前が並ぶと、どちらに書けばよいのか分からなくなります。
  → チャンネル名の重複禁止。
- （質問）チャンネルを作った人を、あとから別の人に交代できますか
  （回答）今回は交代できなくて構いません。あわせて、作った人はそのチャンネルのメンバーから外れられないようにしてください。誰も管理できないチャンネルが残ってしまうためです。
  → 作成者の交代なし＋作成者はメンバーから外れられない。
- （質問）メッセージを直せる期間に制限はありますか
  （回答）制限はありません。いつでも直せて構いません。直したあとは「編集済み」の印が付いたままで構いません。
  → 編集に時間制限なし＋「編集済み」の印は付いたままでよい。
- （質問）「削除されました」と表示されているメッセージに、返信を続けられますか
  （回答）続けられて構いません。むしろ、そこで会話が続けられなくなるほうが困ります。
  → 削除済みメッセージへの返信は継続可。
- （質問）検索は、ログインしていない人も使えますか
  （回答）ログインした人だけで構いません。
  → 検索はログイン必須（未ログインは使えない）。
- （質問）登録に招待や承認は要りますか
  （回答）要りません。社内で使うものなので、メールアドレスがあれば登録できて構いません。
  → 登録に招待・承認は不要（自分で登録できる）。

## 自分で決めたこと（確認不要）

spec・design-guide が「実装の判断」と明記している点などを、こちらで決めたものです。

| 決めたこと | 内容 | 根拠 |
|:--|:--|:--|
| 文字数カウンタ | 入力に追随する動的表示（`248 / 1,000 文字`、超過は赤）にする | design-guide §4「どちらにするかは実装の判断」／ モックの表記 `0 / 1,000 文字` |
| JavaScriptの使用 | スレッドパネルの開閉・メッセージの編集中切り替え・文字数カウンタなどに最小限だけ使う | `mockup/README.md`・design-guide §5「使うかどうかは設計の判断」 |
| 日付の区切り表示 | メッセージ一覧に日付の区切り（例：2026年8月17日（月））を入れる | `channel-show.html` の `day-sep` |
| アバター表示 | 表示名の先頭文字＋人ごとに固定した背景色（design-guide 指定の4色）で表示する | design-guide §1 |
